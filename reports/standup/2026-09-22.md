## Learned

- The "one to two orders above" premise in `0014`'s original loss-magnitude estimate and in
  `losses.ts`'s doc comment was wrong for a specific, now-documented reason: it reasoned from the
  reward range's worst case (`target²` up to 16 at the `−4.0` extreme), but actual rewards —
  including this run's first-step-after-`reset()` samples, which skew *larger* in magnitude than
  mid-episode rewards — never approach that extreme, so raw squared error lands close to
  `continueLoss`'s own order instead of dominating it. The normalization decision itself survives
  this correction; only the magnitude claim that originally motivated it needed fixing.
  `self_checked, medium confidence` (single measurement design, order-of-magnitude-consistent
  with but not numerically identical to the PR #77 reviewer's own sweep).
- Confirmed empirically (not just from the review's description) that computing rollout tensors
  outside a `tf.variableGrads` closure and only referencing them from inside throws "Cannot find a
  connection between any variable and the result" — same failure class `WorldModel.step()`'s own
  `forward()`-must-run-inside-what-differentiates-it comment already documents, now cross-linked
  from `0013`.
