## Learned

- **[high, self_checked, execution-confirmed]** `tf.Variable.assign(tensor)` copies the source
  tensor's data into the variable rather than adopting it — disposing the source tensor immediately
  after `assign()` returns leaves the variable's value correct. Verified directly (`tf.memory()`
  tensor count and `arraySync()` value both checked before/after dispose). This is what makes it
  safe to wrap `assign()`'s source-tensor construction in `tf.tidy` without corrupting the variable
  it targets.
- **[high, self_checked, execution-confirmed]** The `[low]` float32-nondeterminism hypothesis from
  the 2026-07-26 stand-up is retracted: the reviewer's out-of-process reproduction landed
  bit-identically on this run's predecessor's figure (`4.911e-4`), not the reviewer's own original
  number (`5.87e-4`) — ruling out cross-process float32 noise as the explanation. The two
  measurements' actual discrepancy remains unexplained but is no longer attributed to
  nondeterminism; both numbers stay well inside the `5e-3` tolerance and the qualitative conclusion
  (ample margin) is unaffected.
- **[medium, self_checked]** A "helper adds ~Ns to an Ms suite" sentence is ambiguous between "Ms
  is the baseline, N is the delta" and "Ms is the new total" — this project's own commit message
  and stand-up report picked different readings of the same measurement in the same PR. Worth
  phrasing future runtime notes as an explicit before/after pair (e.g., "0.9s → 2.4s") rather than
  an additive one, to avoid the ambiguity outright.
