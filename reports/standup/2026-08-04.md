**Finding #1 fixed, but not via the report's literal sketch.** The report proposed threading an
`Rng`-derived seed into `tf.multinomial(logits, 1, seed)`. Implementing that literally first —
before committing to it — surfaced a problem the report didn't anticipate: on this project's pinned
`@tensorflow/tfjs-node@4.22.0`, `tf.multinomial` with an **identical numeric seed doesn't reliably
reproduce the same draw** across repeated calls in one process (self_checked, high confidence;
repro below). Shipping the literal suggestion would have compiled and looked fixed while remaining
exactly as non-reproducible as before — worse than leaving it open, since it would read as closed.

Repro (executed directly, not from a test file):
```js
const logits = tf.tensor2d([[1, 2, 3], [0, 0, 0]]);
tf.multinomial(logits, 1, 42).arraySync(); // [[2], [2]]
tf.multinomial(logits, 1, 42).arraySync(); // [[2], [0]] — same seed, second row differs
```
Native TF's `Multinomial` op only guarantees determinism when a graph-level seed is also set;
tfjs's `multinomial()` binding has no way to set one, so op-level `seed`/`seed2` alone still pull
fresh entropy per call.

Implemented instead: `sampleHard()` (`src/model/rssm.ts`) now draws via the Gumbel-max trick
(`argmax(logits + Gumbel noise)`, equivalent to `Categorical(softmax(logits))`), with the Gumbel
noise's underlying uniforms drawn directly from the passed-in `Rng.next()` — no TF-native random op
in the reproducibility-critical path. Verified reproducible (same `Rng` seed, two fresh calls,
byte-identical output — new test in `test/model/rssm.test.ts`) and distributionally correct (3000
draws from skewed logits landed within 1% of the softmax proportions, checked directly). Tensor-leak-
checked directly (100 calls, `tf.memory()` before/after): 0 net tensors.

`RSSMCell.prior()`/`.posterior()` gained an optional third `rng` param (after the existing
`fixedHard`); `sampleHard()`/`sampleStraightThrough()` now require `rng` whenever `fixedHard` is

## Learned

- **`tf.multinomial`'s `seed` param isn't a reliable determinism contract on this pinned tfjs-node
  backend.** This is a materially different finding than the quality-pass report's working
  assumption ("threading a seed through fixes it"). Anywhere else in this codebase (there's nowhere
  else yet) or in future code that might reach for `tf.multinomial(..., seed)` expecting
  reproducibility should route through the project's own `Rng` instead — flagging this as a pattern
  to watch for when priority 3 (RSSM completion) and later priorities touch more of the model code.
  self_checked, high confidence (isolated repro above, run three times, same non-reproduction).
- The self-limiting clause's "fix exactly one" reading matters in practice: PR #36's review had to
  spell out that finding #1 belongs to *today's* priority-2 slot, not priority 3, because the report
  itself had proposed the opposite. Worth remembering for future quality-pass reports: propose a
  landing slot for open BLOCKING findings, but expect the human review to be the actual authority on
  sequencing, not the report's own proposal.
