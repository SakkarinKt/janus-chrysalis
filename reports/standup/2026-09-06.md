## Learned
- The five-argument `WorldModel.step()` signature change (adding `done`) was a non-event for this
  experiment specifically because `run.ts` goes through `runEpisode` rather than calling `.step()`
  itself — the abstraction boundary `src/experiment/freeze.ts` provides already insulated this
  script from that signature change. Worth remembering as a general pattern: experiments that call
  `WorldModel.step()` directly (none currently do, per a repo-wide grep) would be the ones actually
  at risk from a signature change like this, not ones going through `runEpisode`.
  `self_checked, high confidence` (confirmed by reading `run.ts`'s only two step-adjacent call
  sites — both `runEpisode(...)` — and `freeze.ts:162`'s `.step(actions[i], ..., result.done)`).
- Re-reading priority 5's named invariant list (`loop/GOAL.md`: "KL free-bits floor, WM/AC gradient
  separation, NaN → graceful halt, continue/termination head") against the current test suite: three
  of the four already have direct tests — free-bits floor (`test/model/losses.test.ts:131`,
  "clips dynLoss/repLoss to exactly freeBits"), NaN → graceful halt (`test/model/worldModel.test.ts`
  lines 307 and 340, `docs/explainers/0009`), and continue/termination head (multiple tests in
  `worldModel.test.ts`, most recently the direct target-polarity pin added on PR #66, still open).
  The fourth, "WM/AC gradient separation," has no test and — as far as I can find — no code to test
  yet: `src/agent/` holds only `QLearningPolicy` (tabular Q-learning, `src/agent/policy.ts`), not a
  neural actor-critic sharing any parameters or gradient path with the world model. There is no
  WM/AC boundary in the tree today for a separation invariant to pin. `self_checked, medium
  confidence` (based on a repo-wide grep for actor/critic/policy-gradient constructs turning up only
  the tabular policy — I did not exhaustively re-derive proposal `0001`'s Arm definitions to confirm
  an AC module isn't planned to land before Gate G2).

- **Process failure, self-reported (PR #67 review, 2026-09-07)**: committed the re-run's output
  over `2026-08-12-arm-a-instrument-validation/`'s existing manifests without checking (a) whether
  the script's re-run was actually seeded the same way as the original (it wasn't —
  `WorldModelConfig.seed` was never threaded into `run.ts`, a landed capability I didn't check
  this script used before assuming a re-run was a same-thing repeat), or (b) whether other
  documents cited the specific numbers I was about to overwrite (`docs/proposals/0001`'s gate
  table does). "Re-run to check compatibility" and "commit the output as if it supersedes the
  original" are different actions, and I conflated them — the compatibility check only needed the
  former. General lesson: before committing over an existing dated artifact directory, check what
  cites its specific numbers and whether the new run actually reproduces them under the same
  configuration, rather than assuming same-script-same-seeds means same-result.
