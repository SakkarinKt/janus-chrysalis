## Learned

- Confirmed directly (not just from the review's framing) that the `train=false` throw path leaks
  exactly zero tensors under the new fix, and that the `train=true` path's remaining ~66-tensor
  delta on a throw is unrelated to `step()`'s own bookkeeping — it reproduces identically whether or
  not `prevState`/`observationTensor` disposal happens at all, and traces to `tf.variableGrads`'
  own internal `tf.tidy` dropping its intermediates on `forward()`'s exception path rather than
  disposing them. `self_checked, high confidence` (isolated by running the `train=false` variant of
  the same repro and comparing `tf.memory().numTensors` deltas: 66 with `train=true`, 0 with
  `train=false`, same wrong-length-observation trigger both times).
- The bug this run fixed is a direct instance of a pattern worth naming for future `try`/`finally`
  use around partially-mutated instance state: a `finally` block that unconditionally disposes
  "the old value" is only safe if the *reassignment* to the new value is unconditional too (or if
  the finally itself is conditioned on which path was taken). Here the reassignment was
  success-only but the disposal wasn't, so the invariant "`this.state`'s tensors are always live"
  broke silently on the throw path — the kind of drift a leak-focused review lens (PR #39's) can
  introduce while fixing a different, real leak, and that only a review pass explicitly trying to
  break the new code (PR #40's) caught. `self_checked, high confidence` (reproduced directly, fix
  verified against the exact reviewer repro).
