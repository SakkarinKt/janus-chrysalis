## Learned

- `noUncheckedIndexedAccess` flags `controlLosses[i]` inside `driftAttributableError` even though
  the preceding length check guarantees it's defined for every `i` the `.map` produces — the
  checker can't correlate two separately-typed arrays' lengths across a conditional. Same class of
  "unproven-safe to the checker, actually safe by construction" diagnostic the quality-pass
  triage rubric (`loop/GOAL.md` priority 2) names; resolved here with an explicit runtime guard
  (throws a distinct "internal error" message if ever reached) rather than a bulk `!`/`as`, so it
  reads as documentation of the invariant instead of a silenced warning. `self_checked, high
  confidence` (direct `tsc`/ratchet before-and-after comparison, isolated by stashing untracked
  new files to get a clean pre-change baseline).
- Re-deriving what "priority 4 — Arm-A metric plumbing" should mean in code terms surfaced a real
  gap worth naming precisely: proposal `0001`'s milestone gate ((a) control flat, (b) intervention
  rises above it) is phrased over each condition's *own* series plus a seed-variance tolerance
  band, not over the intervention-minus-control diff directly — the diff is what makes a rising
  signal visually legible on a plotted curve, but a tolerance-band computation needs multiple
  control-seed runs' variance, which nothing built so far produces. Recorded in
  `docs/explainers/0007`'s "Relationship to the milestone's two-sided gate" section so a future
  run building the actual gate check doesn't have to re-derive this. `self_checked, medium
  confidence` (direct reading of proposal `0001`'s gate language, not checked against the human's
  intent beyond what the text says).
