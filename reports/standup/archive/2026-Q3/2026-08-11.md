- **Bug fix — bootstrap suppression on `done`.** `CooperativeGridWorld.step()`
  (`src/env/gridworld.ts:51`) sets `done = currentStep >= horizon` unconditionally; the
  environment has no absorbing/goal state, so every `done: true` transition is a **time-limit
  truncation**, never a true terminal state with "no next state to bootstrap from." The prior
  `update()` dropped the TD bootstrap term to `0` whenever `transition.done` was `true`, which
  the PR review traced through: rewards are `≤ 0` by `computeReward`'s construction, so the
  dropped bootstrap biased the Q-value of every episode's last transition *upward*, one-sided, on
  exactly the end-of-episode states the drift-attributable-error metric depends on. Fix: `update`
  no longer branches on `transition.done` at all — always bootstraps
  `gamma * max_a' Q(s', a')`. Went with the review's simpler option (always bootstrap, since
  `done` ≡ truncation in this env) over adding a `terminated`/`truncated` split to
  `StepResult`/`Transition`, since this environment has no termination case to distinguish
  *from* yet — documented as the deferred general fix in the explainer, for whenever a future
  environment adds a real absorbing state.
