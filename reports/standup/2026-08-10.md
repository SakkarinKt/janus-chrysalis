  that's safe here specifically and not a general property of arbitrary observations). Ties on an

  generically over any `Policy` with an optional `update` hook, so `QLearningPolicy` is simply the
  first `Policy` for which that gating is observable.

## Learned

- The two array-indexing conventions this codebase has used so far for the identical
  "index is safe by construction, `noUncheckedIndexedAccess` can't see why" situation aren't
  fully reconciled: `freeze.ts`'s `worldModelLoss` line (PR #39) raised the ratchet baseline with
  an explanatory comment; `metrics.ts`'s `driftAttributableError` (PR #42, human-reviewed) added
  an explicit narrowing throw instead, with the review calling that the better match to
  "documentation of the invariant instead of a silenced warning." This run followed the more
  recent, human-endorsed precedent for `QLearningPolicy`'s new code, but didn't touch
  `RandomPolicy`'s pre-existing baseline-tracked line (`policy.ts:35`, same pattern, unfixed) to
  avoid scope creep into code this run didn't otherwise need to touch. `self_checked, medium
  confidence` — the precedent-following judgment call is mine; whether the two existing
  conventions should eventually be reconciled repo-wide is a question for the human, not
  self-resolved here (see "Decisions needed").
- Tabular Q-learning's Q-table has no getter in this minimal design, which made testing the TD
  update's arithmetic indirect (had to infer values via which of two competing "decoy" actions
  `act()` ends up preferring, rather than reading `Q(s,a)` directly). This is a real but
  non-blocking test-ergonomics cost of keeping the class's public surface minimal
  (`act`/`update` only, matching `Policy`'s interface exactly) — noted here rather than adding a
  test-only getter that isn't otherwise needed. `self_checked, high confidence` (direct read of
  the resulting test file).
